# City workload sampler 08 — method only, performance UNVERIFIED

Prepared 2026-09-30 UTC against `city-life.ts`, `main.ts`, the archived integrated-06 sampler/raw record, [independent review 07](reviews/performance-07.md) and the final section of [journey protocol 07](journey-protocol-07.md). This contribution adds only `tools/qa/city-activity-performance.js` and this method. No production behavior, population, route, quality gate or budget changes. No browser/performance run has been performed by its author. A syntax check is not runtime approval; root must obtain independent source review and the exclusive hardware lock before running.

## Frozen procedure

- Full world, `?qa=1`, profiler absent/off, ordinary outdoor play, unmounted/unseated, visible foreground tab, no held inputs. Refuses concurrent existing world sampler or journey observer. Use an externally backed-up disposable save and keep the production bundle, asset files, sampler, commit/dirty manifest and hardware record frozen throughout. The caller supplies their hashes/disclosures; the helper records these assertions plus actual script URLs and WebGL hardware, but does not independently hash served bytes or verify that Blender/other processes are idle.
- Same market route `(20,-300) → (20,-318) → (20,-300)`, camera pitch `.22`, distance `6.2`, waypoint yaw, Low / resolution `.7` / shadows `512` / vegetation `.3` / reflections off / AA `1` / post off / draw distance `90` / nearby visibility. Inherit and record other entry settings, set `freezeTime=true`, `timeSpeed=1`. Use the preceding accepted experiment's **1280×720, DPR 1.25, internal 1120×630** when comparing at that configuration. Actual viewport/DPR/internal dimensions are recorded and must remain unchanged; the sampler does not resize the browser. Different dimensions require separate labeling.
- Preserve entry raw storage, original save object, full live behavioral snapshot, player/bicycle/camera state and city navigation state. Set `.30` once, reset city residents through their existing reset method, reset habitat/siltfin through their existing methods, set world elapsed to `0` and `reedwingSeen=false`, then place the player at the declared market start. Habitat reset uses the runtime's constructor-initial records; it is not necessarily a fresh wildlife save. Other original discoveries/activities/appearance stay part of the disclosed fixture. Record this full initial fixture.
- Run **180 active-world seconds** of ordinary RAF-driven simulation while standing at the route start. This is neither a tight simulation loop nor accelerated time. Record real elapsed time, actual active seconds and the final frame's small overshoot. Save the resulting `.30` work fixture, including all ten resident logical states/positions/routes/timers, pending navigation job/heap/maps, cache arrays, habitat records/remainder, village actors and other exposed world snapshots. Failed arrivals remain present; never teleport residents to workplaces.
- Restore that same settled behavioral/navigation fixture before **each** repeat. Check equality of the saved world, city resident logical state and navigation snapshot before proceeding. The three work repeats retain `.30`; the three errand-transition repeats change to `.52` exactly once after restoration. Each repeat starts at the same player/camera route placement, walks a **10-second** warmup and then **60 seconds** of RAF delivery measurement. Work precedes errand transition. The initial 180-second settle occurs once; it is not silently rerun for different results. No additional settling is added to the errand transition.
- Full before/after snapshots, resident destination-validity checks, fixture equality checks and loaded-state reads occur outside timing. After the before snapshot, the next RAF is the timing anchor; record that small untimed boundary gap and the actual anchor's position/world elapsed/counts. Warmup/measurement can overrun by one frame, recorded honestly. Absolute RAF timestamps plus interval arrays preserve each raw sample. One-second traces only read scalar player position/speed, clock, ten resident status/visibility counts, renderer counters and optional JS heap. No screenshots, video, profiler, deep scene traversal, collision checks or serialization during timing. The first start-line crossing may finish a lap begun during warmup; `fullTimedLaps` excludes it and waypoint events retain the path evidence.

## Invocation and control

Root injects the exact frozen file through its browser tooling/devtools; injecting alone does not start it. Fill these strings from actual frozen provenance, not example values:

```js
beginCityActivityPerformance({
  provenance: {
    commit: 'ACTUAL_COMMIT',
    dirtyManifestSha256: 'ACTUAL_MANIFEST_SHA256',
    bundleSha256: 'ACTUAL_SERVED_BUNDLE_SHA256',
    samplerSha256: 'ACTUAL_SAMPLER_SHA256',
    hardwareRecord: 'PATH_OR_ID_OF_ACTUAL_HARDWARE_RECORD',
    exclusiveLock: 'ACTUAL_LOCK_ID_AND_EXCLUSIONS',
    saveDisclosure: 'ACTUAL_DISPOSABLE_SAVE_ID_AND_ALL_PRIOR_FIXTURE_EDITS'
  }
});
__cityActivityPerformance.poll(); // compact status; does not serialize evidence
__cityActivityPerformance.stop('Operator reason'); // aborts promptly and restores provisionally
// Poll until running:false, or await finished outside a long browser-tool call.
__cityActivityPerformance.export(); // JSON string; retain externally before navigation
```

Start returns immediately; RAF promises yield between frames and the page stays interactive. Prefer short start/poll tool calls, not a browser evaluation awaiting the whole roughly ten-minute session. Export refuses while running. Keep incomplete/aborted runs and their available raw samples; do not replace them invisibly. Bounds are six runs, 36,000 intervals and 65 scalar traces per run, 64 timed waypoint events, a 15-minute session cap, 6-second movement-stall limit and a 2.5-second missing-RAF watchdog. Hidden tab, blur, external key/pointer/wheel input, resize, context loss, mode/controller/settings/time changes or a measured ≥500 ms frame gap abort. The latter gap is retained: the game excludes such gaps from active simulation. These checks do not detect every possible external script/state intervention.

## What the evidence establishes

All ten residents continue normal schedule/path/task simulation, including blocked routes, greetings and offscreen activity. Their **actual** instantiation and group/ancestor visibility are recorded; ten logical residents do not mean ten visible workers. `renderEligible` follows the source's 3D distance radius clamp (`nearby 90` here). Group visibility is not a frustum/occlusion/pixel test. Endpoints include activity/status, destination distance, route, task/meeting/conversation counters, hand-contact error and position/destination validity. Scalar timed counts reveal whether travel ends early. Failed work arrivals are explicitly listed and prevent `fullySettledWork`; invalid positions/destinations flag the run. Review all six records, actual population/status counts and route completions before applying a workload label. In particular, `.52` is **errand transition**, never automatically sustained crowd activity.

Loaded-state records include asset presence, scene-root child counts, instantiated city/village characters, habitat population, navigation/collision revision and renderer counts. Character allocations and renderer caches remain warm across repeats; characters first instantiated later remain allocated. No hidden preload of all ten characters is added. This records loading/settling overhead and changing resource counts, but does not measure cold loading, GPU uploads, shader stalls or true resource residency. JS heap samples include the sampler's retained evidence arrays; observed maxima are neither true peak nor post-cleanup settled memory, and are not process/GPU memory. Never combine or relabel the previous `.12` home/rest data as this active workload. Matched candidate comparisons must use this same method, provenance and configuration.

## Restoration and remaining limits

The restore adapter is deliberately source-bound and refuses known missing runtime fields. It restores logical city state **and** its pending search/navigation caches instead of merely resetting residents. It also restores exposed habitat/village records, world clock, siltfin saved state and player/camera values. Animation mixers, warm character allocations, GPU caches, unexposed ambient wildlife, the main internal shader clock, autosave timer and exact pose/contact history are **not** checkpointed. Habitat poses are rebuilt; siltfin uses its normal clock-reset resynchronization on the next frame. Ten seconds of ordinary warmup follows every restoration. This is a reproducible disclosed behavioral fixture, not a bit-identical full-engine checkpoint.

Completion/abort releases inputs, restores original settings and live logical snapshot, pauses the UI, and records immediate restoration/storage checks. This is **provisional**: paused rendering can still advance city navigation, and autosave plus `beforeunload` can overwrite local storage. No automatic reload is performed and no exact original-world reconstruction is claimed. `original.storageRaw` preserves the entry persisted save byte-for-byte; `original.behavior.save` preserves the live entry world and may differ from the persisted save, while `original.saveObject` also retains any stale saved subsystem copies. The actual live entry position is `original.behavior.player.position`.

**Root's required recovery after export:** navigate to the intentionally script-free same-origin `qa-storage.html` recovery page first; then install the desired exported save there, and only then navigate normally back to the game. Restoring entry persisted storage means using `original.storageRaw` exactly, removing the key if it was null. Restoring live entry instead means cloning `original.behavior.save`, assigning its outdoor `position` from the captured player `[x,z]`, and serializing that clone. The app's normal validation/migration and fresh runtime construction still apply. Installing storage before leaving the active app can lose the restoration to its unload persistence. Root owns this explicit recovery and verifies the resulting loaded world; the helper does not modify the recovery page or perform it silently.
